# B-4 — Local-CCU detection

**✅ done 2026-09-04** (`4.3.0`).

When Node-RED runs on the CCU itself (RedMatic), the interface processes
can be reached directly on their 3xxxx ports — BINRPC for BidCos and
ReGa, and without the hop through the CCU's lighttpd proxy. The
connection node picked that up from:

```js
const rfdConf = fs.readFileSync('/etc/lighttpd/conf.d/proxy.conf').toString();
if (rfdConf.match(/"port"\s+=>\s+32001/)) {
  this.isLocal = true;
}
```

On current firmware that file is a single line:

```
include "/var/etc/lighttpd_proxy.conf"
```

which itself only contains `include "/etc/lighttpd/conf.d/proxy_normal.conf"` —
the `"port" => 32001` markers are two levels down the include chain.
So the regex has not matched in years and every local install silently
went through the proxy on 1999/2000/2001/2010/9292.

Measured on a lab CCU3 with firmware 3.89.8: `proxy.conf` is the bare
include above, while 31999, 32001, 32010 and 39292 are all listening.

## Fix

`nodes/lib/localccu.js` asks the kernel instead of parsing lighttpd's
configuration: a listener on rfd's direct port (32001, or the ReGa's 31999) is exactly the condition that makes using the direct ports
correct, and it cannot drift when eQ-3 reorganises the config files
again. `/proc/net/tcp` and `/proc/net/tcp6` are plain files, so the check
stays synchronous — the interface table is built in the constructor —
and on a host without `/proc` (Windows, macOS) it simply reports "not
local", which is the safe answer.

8 unit tests, including the real `/proc/net/tcp` line format from the
3.89.8 lab box.
